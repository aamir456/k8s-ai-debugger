k8s-ai-debugger · architecture

How Claude sees the cluster

A notes app runs on a local kind cluster with Prometheus and Grafana. Claude investigates it through the open-source kubernetes-mcp-server, running read-only in a container on the same Docker network.

Path 1 · cluster state

Claude asks about pods

  1. You ask a question in Claude Code.
  2. Claude calls a tool such as pods_list_in_namespace.
  3. The MCP server calls kube-apiserver with the mcp-viewer token.
  4. RBAC allows reads; Secrets and writes are refused.
Path 2 · alerts and history

Claude starts from an alert

  1. Prometheus scrapes the app and kube-state-metrics every 15s.
  2. A rule such as RedisDown fires to Alertmanager.
  3. Claude calls get_alerts, then PromQL with execute_range_query.
  4. It drills into pods, events and logs to confirm the cause.
Path 3 · you

You watch the same signals

  1. The browser hits localhost:8080, mapped to the control-plane node.
  2. Envoy routes by Host header to the app or Grafana.
  3. Grafana queries the same Prometheus Claude uses.
  4. chaos.ps1 breaks and resets the app with your admin kubectl.

What the AI identity can and cannot do

  • allowedRead pods, logs, events, Deployments, Services, HPAs, nodes
  • allowedPod and node metrics, PromQL, alerts, silences (read)
  • allowedRead PrometheusRules, PodMonitors, ServiceMonitors
  • deniedSecrets (RBAC + denied_resources)
  • deniedAny write: scale, patch, delete, exec, create silences
  • deniednodes/proxy, and every other kubeconfig context such as EKS
